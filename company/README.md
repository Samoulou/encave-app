# EnCave — le cerveau de l'entreprise

Ce dossier est la mémoire commune de l'entreprise. Tout agent qui travaille pour EnCave — le CEO, un spécialiste, une session Claude Code — commence ici. Ce qui n'est pas écrit ici n'est pas décidé.

| Document                             | Ce qu'il tranche                                                       | Qui le tient à jour        |
| ------------------------------------ | ---------------------------------------------------------------------- | -------------------------- |
| [CAP.md](./CAP.md)                   | L'ambition, la définition de « n°1 », les objectifs et les indicateurs | CEO, validé par Sam        |
| [MODELE.md](./MODELE.md)             | Comment EnCave gagne de l'argent : prix, marges, leviers de croissance | CEO + Finance              |
| [PRODUIT.md](./PRODUIT.md)           | Ce que le produit fait aujourd'hui et ce qui vient ensuite             | Produit                    |
| [ORGANISATION.md](./ORGANISATION.md) | Qui fait quoi, comment le travail circule, les rituels                 | CEO                        |
| [AUTONOMIE.md](./AUTONOMIE.md)       | Ce que les agents décident seuls et ce qui reste à Sam                 | Sam                        |
| [PRIORITES.md](./PRIORITES.md)       | Ce qu'on fait maintenant, les décisions ouvertes, le journal           | CEO, à chaque session      |
| [BRIEF-CEO.md](./BRIEF-CEO.md)       | Les instructions à donner au CEO (Claude Duet / Claude Project)        | Sam                        |
| [chantiers/](./chantiers/)           | Un fichier par chantier en cours qui dépasse une session               | Le spécialiste responsable |

Le reste du dépôt :

- `CLAUDE.md` — les règles techniques du code. Un agent qui touche au code les suit à la lettre.
- `docs/` — la documentation technique et opérationnelle de l'application : architecture, ADR, runbooks, protocoles de test, conformité, rapport d'audit.
- `.claude/agents/` — la définition de chaque spécialiste.

## Règles d'écriture

- **Une information, un endroit.** Si elle existe déjà ailleurs, on fait un lien.
- **Un fait porte sa date et sa source.** « 12 caves actives (admin, 13.11.2026) », jamais « une dizaine de caves ».
- **Une hypothèse est marquée comme hypothèse.** Les chiffres de scénario ne sont pas des résultats.
- **On supprime ce qui est périmé.** L'historique est dans Git ; un document faux coûte plus cher qu'un document absent.
