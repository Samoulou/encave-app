# ENC-144 — Audit a11y rapide avec axe-core sur pages publiques

## Objectif métier

Garantir que les pages publiques critiques du tunnel de conversion (découverte → réservation → confirmation) sont accessibles aux personnes en situation de handicap (visuel, moteur, cognitif). L'a11y est un critère de qualité produit attendu par notre cible premium et un facteur SEO. À court terme : viser **0 erreur axe-core critique** sur les 3 pages cible avant ouverture publique.

## Acteurs

- CLIENT (principal) — visiteur public, utilisateurs lecteurs d'écran, navigation clavier
- Équipe dev (interne) — pilotage de l'audit

## Préconditions & déclencheurs

- Pages cible accessibles en environnement Preview (Vercel) ou Staging (`encave-dev.vercel.app`)
- Stack axe-core installé (via `@axe-core/playwright` pour intégration E2E)
- Déclenchement : audit ponctuel pré-MVP, puis run en CI sur chaque PR ciblant `main`

## User stories

> En tant que **client utilisateur de lecteur d'écran**, je veux pouvoir parcourir le détail d'une expérience, réserver et confirmer mon achat sans rencontrer d'obstacle bloquant, afin de finaliser ma réservation en autonomie.

> En tant que **dev**, je veux un test axe-core automatisé en CI sur les 3 pages critiques, afin de prévenir toute régression a11y avant merge.

    Alors le statut du check est "failed" et le merge est bloqué

## Règles métier

- **Pages cible (3)** :
  1. Détail expérience : `/[locale]/experiences/[winerySlug]/[experienceSlug]`
  2. Checkout : `/[locale]/checkout/[bookingRef]`
  3. Confirmation : `/[locale]/bookings/[bookingRef]/confirmation`
- **Référentiel** : WCAG 2.1 niveau AA (config axe-core par défaut + tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`)
- **Seuils de succès** :
  - 0 violation `critical`
  - 0 violation `serious`
  - Violations `moderate` / `minor` : documentées dans un ticket de suivi mais n'échouent pas la CI
- **Procédure** :
  1. Run local via script `npm run a11y:audit` (à créer) qui lance Playwright sur les 3 pages en FR/DE/EN
  2. Intégration CI via job GitHub Actions sur PR → `main` (utilise `@axe-core/playwright`)
  3. Rapport JSON archivé en artefact CI pour traçabilité
- **Couverture i18n** : audit run sur les 3 locales (FR, DE, EN) — un attribut `lang` mal positionné est une violation
- **Couverture états** : checkout testé en state initial + state "formulaire incomplet" (erreurs visibles)

## Cas limites

- Modale checkout (calendrier, conditions 18+) : doit être incluse dans le scan, axe-core scan le DOM courant
- Composants shadcn/ui (Dialog, Select) : déjà a11y-friendly via Radix, vérifier que l'usage n'introduit pas de régression (ex: `aria-label` manquant sur trigger)
- Page confirmation avec QR code : `<Image>` du QR doit avoir un `alt` explicite (cf ENC-068b)
- Mode dark/light : audit run sur le thème par défaut (clair). Le thème dark sort du périmètre MVP
- Tests E2E flaky si réseau lent → timeout axe à 30s sur chaque page

## Hors-périmètre explicite

- **Pas** d'audit manuel lecteur d'écran (NVDA/JAWS/VoiceOver) — reporté post-MVP
- **Pas** d'audit des pages encaveur (dashboard) — couvert dans un futur lot
- **Pas** de contrast ratio fix global (couvert au cas par cas si flag par axe)
- **Pas** de remediation des violations `moderate`/`minor` dans cette US

## Métriques de succès

- 0 violation `critical` ou `serious` sur les 3 pages × 3 locales = 9 scans verts
- Job CI `a11y-audit` exécuté sur 100% des PR vers `main` après livraison
- Temps de run CI < 2 min
