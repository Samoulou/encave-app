# ENC-150 — Audit complet emails : deliverability + rendu mobile

## Objectif métier

Les emails transactionnels EnCave (confirmation réservation, rappels J-1 et H-2, follow-up, welcome encaveur, KYC, reset password) sont **critiques** : un email en spam = un client qui rate son rendez-vous, un encaveur perdu en onboarding. On doit garantir une délivrabilité maximale (boîte de réception, pas onglet "Promotions" Gmail) et un rendu impeccable sur mobile (90% des ouvertures attendues).

## Acteurs

- CLIENT (principal) — reçoit confirmation, rappels, reçu PDF
- WINEMAKER (principal) — reçoit welcome, KYC, notifs nouvelle résa, payout
- ADMIN (secondaire) — emails de modération winery

## Préconditions & déclencheurs

- Domaine `encave.ch` configuré côté Resend
- Tous les templates React Email existants dans `src/server/email/templates/`
- Accès DNS du domaine (Infomaniak/Vercel DNS) pour SPF/DKIM/DMARC
- Outil de test deliverability choisi (cf questions ouvertes)
- Déclenchement : audit ponctuel pré-bêta Fondateurs

## User stories

> En tant que **client**, je veux recevoir l'email de confirmation en boîte de réception (pas spam) et pouvoir le lire confortablement sur mon iPhone dans le train, afin de retrouver mon QR code le jour-J.

> En tant qu'**encaveur**, je veux que mes notifs de nouvelles réservations arrivent fiablement et soient lisibles depuis mon Android, afin de ne pas rater une résa.

## Règles métier

- **Templates à auditer (liste exhaustive)** :
  1. `BookingConfirmation` (client) — le plus critique
  2. `BookingReminder24h` (client)
  3. `BookingReminder2h` (client)
  4. `BookingFollowUp` (client, post-event)
  5. `BookingCancelledByWinery` (client) — refund auto
  6. `WelcomeWinemaker` (encaveur)
  7. `KycReminderD1` (encaveur)
  8. `NewBookingNotification` (encaveur)
  9. `PayoutNotification` (encaveur)
  10. `ResetPassword` (commun)

- **Checklist DNS (SPF/DKIM/DMARC)** :
  - SPF : `v=spf1 include:_spf.resend.com ~all` (pas de `?all` permissif)
  - DKIM : 2 enregistrements CNAME Resend (`resend._domainkey` + variante) propagés
  - DMARC : `v=DMARC1; p=quarantine; rua=mailto:dmarc@encave.ch; pct=100` (commencer en `quarantine`, passer `reject` après 30j sans incident)
  - DKIM aligné (d= matche From) — vérifier via mail-tester

- **Clients email à tester (4 minimum)** :
  - Gmail web (desktop)
  - iOS Mail (iPhone, dernière version iOS)
  - Gmail Android (app native)
  - Outlook web (Outlook.com) — couvre aussi Hotmail
  - Bonus si possible : ProtonMail web, Apple Mail macOS

- **Seuils de succès** :
  - Mail-Tester : ≥ 9/10 par template
  - Inbox placement Gmail : onglet "Principal" (pas Promotions)
  - Rendu mobile : 0 breakage layout, QR ≥ 200px, CTA tap-target ≥ 44px
  - Temps de remediation post-audit : < 2 jours pour les blockers

- **Procédure** :
  1. Vérifier DNS via mxtoolbox.com et dmarcian
  2. Envoyer chaque template à l'adresse mail-tester.com — noter le score
  3. Envoyer chaque template via Litmus/Email on Acid sur les 4-6 clients
  4. Capture d'écran de chaque rendu, archivée dans `docs/audits/emails-2026-XX/`
  5. Ticket de remediation par anomalie

- **From / Reply-to** :
  - From : `EnCave <noreply@encave.ch>`
  - Reply-to : `bonjour@encave.ch` (mailbox surveillée)

## États UI

Pas d'UI applicative. Livrable = rapport d'audit + tickets de remediation.

- **Loading** : n/a
- **Empty** : n/a

## Cas limites

- **Liens tracking** : Resend peut injecter du tracking → vérifier que ça ne flag pas en spam. Désactiver le tracking de clic sur emails sensibles (reset password notamment).
- **Dark mode iOS Mail** : iOS Mail inverse les couleurs automatiquement. Vérifier que le logo et le QR code restent lisibles (fournir version SVG avec fond transparent ou meta `color-scheme: light dark`).
- **QR code email confirmation** : doit être en PNG inline base64 ou pièce jointe (cf ENC-068b). À tester : certains clients (Outlook desktop) bloquent les images distantes par défaut.
- **Caractères suisses** : "œ", accents, "ß" allemand — vérifier encodage UTF-8 sur Outlook.
- **Préheader text** : doit être présent sur chaque template (1ère ligne visible en boîte de réception). Inventorier et compléter si manquant.
- **List-Unsubscribe header** : requis par Gmail et Yahoo depuis 2024. Vérifier que Resend le pose automatiquement (sinon le poser manuellement sur emails marketing — pas transactionnels).

- **Pas** de refonte des templates email (audit seulement, remediation en tickets séparés)
- **Pas** d'A/B testing objet/contenu — post-MVP
- **Pas** de tracking d'ouverture/clic en production (PostHog email reporté)
- **Pas** d'emails marketing / newsletter (transactionnel uniquement pour MVP)

## Métriques de succès

- Score Mail-Tester ≥ 9/10 sur 10/10 templates
- 0 template flaggé en spam / Promotions sur Gmail (compte test neuf)
- DMARC aligné (DKIM pass + SPF pass) sur 100% des envois sortants en J+7 post-audit
- Taux de bounce < 2% sur les 100 premiers envois prod (mesuré via dashboard Resend)
