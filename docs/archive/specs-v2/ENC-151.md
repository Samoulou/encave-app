# ENC-151 — Audit Lighthouse pages publiques

## Objectif métier

Les pages publiques sont la vitrine d'EnCave et le tunnel de conversion. Sur mobile, où ~70% du trafic est attendu, chaque seconde de latence = -7% conversion (étude classique). On vise un Lighthouse Performance ≥ 90 mobile sur les pages stratégiques avant ouverture publique. C'est aussi un prérequis SEO (Core Web Vitals dans le ranking Google).

## Acteurs

- CLIENT (principal) — visiteur mobile en 4G, parcours découverte
- Équipe dev (interne) — pilotage des optims

## Préconditions & déclencheurs

- Pages publiques déployées en environnement Staging (`encave-dev.vercel.app`) ou Production
- Données seed représentatives (≥ 20 wineries, ≥ 50 expériences avec photos)
- Déclenchement : audit ponctuel pré-ouverture publique + régression CI sur PR `main`

## User stories

> En tant que **visiteur mobile en 4G**, je veux que la page d'accueil et le détail d'une expérience chargent en < 2.5s (LCP), afin de ne pas abandonner avant même d'avoir vu le contenu.

> En tant qu'**équipe produit**, je veux un score Lighthouse mesuré régulièrement, afin de détecter toute régression perf avant prod.

## Règles métier

- **Pages cible (4)** :
  1. Homepage : `/[locale]` (FR par défaut)
  2. Listing expériences : `/[locale]/experiences`
  3. Détail expérience : `/[locale]/experiences/[winerySlug]/[experienceSlug]` (échantillon : la 1ère expérience seed)
  4. Landing pro : `/[locale]/pro`

- **Seuils de succès (mobile, throttling Slow 4G simulé)** :
  | Catégorie | Seuil bloquant | Seuil cible |
  |---|---|---|
  | Performance | ≥ 85 | ≥ 90 |
  | Accessibility | ≥ 90 | ≥ 95 |
  | Best Practices | ≥ 85 | ≥ 90 |
  | SEO | ≥ 90 | ≥ 95 |

- **Core Web Vitals (mobile)** :
  - LCP (Largest Contentful Paint) : < 2.5s
  - CLS (Cumulative Layout Shift) : < 0.1
  - INP (Interaction to Next Paint) : < 200ms (a remplacé FID en mars 2024)

- **Méthode de mesure** :
  - **Audit initial** : PageSpeed Insights (PSI) via API, run 3 fois, prendre la médiane (PSI agrège déjà field data si dispo)
  - **CI régression** : Lighthouse CI (`@lhci/cli`) en GitHub Actions, run sur Vercel Preview URL après deploy, configuration mobile (`emulatedFormFactor: mobile`, throttling `mobileSlow4G`)
  - **Field data** : PageSpeed Insights agrège CrUX (utilisateurs réels Chrome). À consulter post-ouverture publique pour valider que le lab data correspond au terrain.

- **Pages exclues du périmètre** :
  - Pages auth (signin, signup) — taille faible, perf rarement un sujet
  - Pages dashboard encaveur — non publiques
  - Pages admin
  - Checkout (testé séparément dans ENC-144 pour a11y, perf vérifié manuellement)

- **Optims attendues si seuils non atteints** (à investiguer, pas inclus ici) :
  - Next.js `<Image>` avec `priority` sur LCP image
  - Lazy-loading photos sous le fold
  - Réduction taille bundle JS (code splitting routes lourdes)
  - Préchargement font Manrope avec `next/font`
  - Éviter `'use client'` superflu (cf CLAUDE.md)

## Cas limites

- **Variance Lighthouse** : le score lab peut varier ±5 points entre 2 runs. Run minimum 3 fois et prendre la médiane.
- **Lighthouse local vs Vercel** : auditer sur Vercel Preview, pas en `localhost` (HMR React fausse les mesures).
- **Locale FR par défaut** : audit principal en FR. Vérifier que DE et EN n'introduisent pas de régression (font fallback différent ? non normalement).
- **Cookies banner ENC-133** : peut impacter LCP si overlay bloquant. À auditer avec et sans banner accepté.
- **Détail expérience avec galerie photos** : le LCP est probablement la 1ère photo. Vérifier `priority` sur cette image.
- **PostHog / Sentry scripts** : analyser leur poids (peuvent dégrader Best Practices et Performance). Charger en `afterInteractive`.
- **Marché 4G Suisse romande** : couverture excellente, mais auditer en Slow 4G simulé reste la bonne pratique (clients en train, vallées du Valais).

## Métriques de succès

- 4 pages × score ≥ seuils cibles = 16 scores verts
- Job `lighthouse-ci` exécuté sur 100% des PR vers `main`
- LCP médian < 2.5s mesuré post-ouverture (CrUX, 28 jours rolling)
- Aucune régression de plus de 5 points entre 2 PR successifs (gate CI)
