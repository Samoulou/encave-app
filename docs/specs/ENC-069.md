# ENC-069 — Génération + attachement `.ics` à l'email de confirmation

## Objectif métier
Un client confirmé doit pouvoir ajouter son expérience à son agenda en 1 clic depuis l'email. Sans `.ics`, il doit recopier date, heure et adresse à la main — friction qui augmente les no-show. Un fichier calendrier proprement formé réduit les oublis et améliore la deliverability perçue de l'email.

## Acteurs
- **CLIENT** : reçoit le `.ics` en pièce jointe, l'ouvre dans son client mail / calendrier.
- **WINEMAKER** : indirectement, voit moins de no-show.

## Préconditions & déclencheurs
- Déclencheur : envoi du `BookingConfirmationEmail` après transition `PENDING_PAYMENT` → `CONFIRMED`.
- Le booking doit avoir une session liée avec `startsAt`, `endsAt`, et la winery doit avoir une adresse résolue (lat/lng + adresse postale).
- Génération côté serveur Next.js (Node), pas Resend.

## User stories
- En tant que **client**, je veux ajouter ma réservation à mon agenda en 1 clic depuis l'email pour ne pas l'oublier.
- En tant qu'**encaveur**, je veux que mes clients arrivent à la bonne heure au bon endroit.

## Règles métier
- **Format** : iCalendar (RFC 5545), encoding UTF-8, line-ending CRLF.
- **Fuseau horaire** : `Europe/Zurich` (avec bloc VTIMEZONE complet, pas juste TZID). Toutes les expériences EnCave sont en Suisse romande pour MVP.
- **UID** : `booking-{bookingReference}@encave.ch` — stable, permet update/cancel ultérieurs avec même UID.
- **SEQUENCE** : `0` à la création, à incrémenter si on émet plus tard un update (V2).
- **METHOD** : `REQUEST` pour confirmation, `CANCEL` pour annulation.
- **PRODID** : `-//EnCave//Booking//FR`.
- **SUMMARY** : `{experienceTitle} — {wineryName}`.
- **LOCATION** : adresse postale complète, formattée `{street}, {postalCode} {city}`.
- **DESCRIPTION** : 
  - Référence : `ENC-XXXXXX`
  - Nombre de participants
  - Lien : `https://encave.ch/fr/mes-reservations/{bookingId}`
  - Note : "Présentez votre QR code à votre encaveur."
- **GEO** : `{lat};{lng}` si disponibles (depuis `Winery.latitude/longitude` via OSM Nominatim).
- **ORGANIZER** : `mailto:no-reply@encave.ch` avec `CN="{wineryName} via EnCave"`.
- **ATTENDEE** : `mailto:{clientEmail}` avec `CN="{clientFirstName} {clientLastName}"`, `PARTSTAT=ACCEPTED`, `RSVP=FALSE`.
- **VALARM** : 1 rappel intégré 2h avant le début (`-PT2H`), action `DISPLAY`, description courte.
- **Nom du fichier attaché** : `encave-{bookingReference}.ics`, MIME `text/calendar; charset=utf-8; method=REQUEST`.

## États UI
- **Loading** : N/A.
- **Empty** : N/A.
- **Error** : si la génération `.ics` échoue, l'email part **sans** l'attachement (le QR et le corps restent prioritaires). Log error + Sentry.
- **Populated** : email avec `.ics` attaché + section "Ajoutez à votre agenda" dans le corps.

## Cas limites
- Adresse cave incomplète (pas de rue) : on remplit `LOCATION` avec ce qu'on a (`{postalCode} {city}`) + warn log.
- Pas de coordonnées GPS : on omet `GEO` (champ optionnel).
- Booking pour 2 personnes : `SUMMARY` ne mentionne pas le nombre, mais `DESCRIPTION` oui.
- Email envoyé en de/en : `SUMMARY` reste en FR pour MVP (le titre de l'expérience peut être en FR). À documenter, sortir traductions du calendrier en V2.
- Outlook desktop : tester explicitement (souvent le plus capricieux).
- Annulation par encaveur (ENC-045) : `.ics` METHOD:CANCEL attaché à l'email d'annulation pour nettoyer l'agenda côté client.

## Dépendances
- Lib : `ics` (npm, maintenue) ou implémentation manuelle simple (recommandé : `ics` pour gestion VTIMEZONE).
- Service : `src/server/services/ics.service.ts` — fonction `generateBookingIcs(booking, type: 'REQUEST' | 'CANCEL'): string`.
- Integration : enrichir `BookingConfirmationEmail.send()` et `BookingCancelledByWineryEmail.send()`.
- Pas de migration DB.

## Hors-périmètre explicite
- Pas de mise à jour `.ics` automatique en cas de modif d'horaire encaveur (V2 : METHOD:REQUEST avec SEQUENCE++).
- Pas de calendrier pour les invités +1 (cf. ENC-084 — décider plus tard).
- Pas de feed `.ics` "tous mes bookings EnCave" (V2, espace client).
- Pas de RSVP bidirectionnel via le `.ics`.

## Métriques de succès
- > 60 % d'ouvertures de l'attachement `.ics` (tracking via Resend ou heuristique).
- Baisse mesurable du taux de no-show entre cohortes pre/post `.ics` (cible : −2 points).
