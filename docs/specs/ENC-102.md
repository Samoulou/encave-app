# ENC-102 — Liste check-in manuelle sur page détail événement (fallback)

## Objectif métier
Permettre à l'encaveur de check-in un client sans scanner son QR : caméra indisponible, client sans téléphone, QR effacé. C'est le filet de sécurité opérationnel pour que le jour-J ne tombe jamais à cause d'une feature technique.

## Acteurs
- **WINEMAKER** (acteur unique) : clique sur "Marquer présent" en face d'un booking.
- **CLIENT** : sujet passif. Pas d'interaction.

## Préconditions & déclencheurs
- Encaveur authentifié, propriétaire de la winery.
- Page détail événement (ENC-096) chargée, session du jour visible.
- Au moins un booking `CONFIRMED` dans la liste.
- Bouton "Marquer présent" affiché en face de chaque booking `CONFIRMED` d'une session "active" (du jour ou en cours).

## User stories
- En tant qu'**encaveur**, je veux pouvoir cocher manuellement un client comme présent depuis la liste de la page détail événement, afin de ne pas être bloqué si le QR ne fonctionne pas.
- En tant qu'**encaveur**, je veux une confirmation rapide (toast vert) après le check-in manuel, afin de continuer à gérer l'arrivée des autres clients.

## Règles métier
- **Bouton "Marquer présent"** : visible si `booking.status === CONFIRMED` ET session dans fenêtre H-2 / H+4 par rapport à `now()`.
- **Bouton "Annuler le check-in"** : visible si `booking.status === COMPLETED`. Pas de fenêtre temporelle (l'encaveur peut corriger plus tard).
- **Bouton combo "Annuler no-show puis présent"** : visible si `booking.status === NO_SHOW`. Action atomique côté serveur (transaction : undoNoShow → checkIn).
- **Confirmation** :
  - Check-in : popover inline léger (un seul clic après preview).
  - Annulation check-in : modale (action plus engageante car potentielle erreur opérationnelle).
  - Annuler no-show + check-in : modale avec texte explicite.
- **Optimistic UI** : la ligne se met à jour immédiatement (badge "Présent à …"), rollback si erreur.
- **Mobile-first** : les boutons doivent être tappables (44×44 min). Sur mobile la confirmation est un bottom sheet plutôt qu'un popover.
- **Source tracking** : appeler `checkInBooking({ bookingId, source: 'manual' })` (différencier du scan dans les logs).
- **Pas de droit en lecture seule** : seul l'encaveur propriétaire peut, vérifié dans l'action.

## États UI
- **Loading (pendant l'action)** : bouton remplacé par spinner inline, autres lignes non bloquées (`useTransition` granulaire par ligne).
- **Empty** : si la session n'a aucun booking CONFIRMED, la colonne action est vide (cf. ENC-096).
- **Error** : toast rouge + rollback optimistic.
- **Populated** : bouton "Marquer présent" en bouton primaire de la ligne (variant `default` pour CONFIRMED, `outline` pour les autres états).

## Cas limites
- **Encaveur clique deux fois rapidement** : `useTransition` empêche le double-trigger, second clic ignoré.
- **Encaveur a deux onglets** : optimistic UI peut désynchroniser. Au retour de l'action serveur, on rafraîchit la ligne avec la vérité serveur. Si conflit (autre onglet a déjà check-in), toast "Déjà enregistré".
- **Session en cours avec 30+ inscrits** : performance OK, chaque ligne est indépendante.
- **Booking annulé entre l'affichage et le clic** : action retourne `BOOKING_CANCELLED`, ligne se rafraîchit avec badge annulé.
- **Booking déjà passé en `COMPLETED` via le scan** : action retourne `ALREADY_CHECKED_IN`, toast informatif + refresh.
- **Pas de JavaScript (très edge case mobile)** : page reste lisible mais les actions ne fonctionnent pas. Fallback : link `data-href` (acceptable car le scénario nominal du jour-J nécessite JS de toute façon).

## Dépendances
- **Autres US** :
  - ENC-096 (page hôte, contient la liste)
  - ENC-101 (action server `checkInBooking`)
  - ENC-103b (interaction avec NO_SHOW, action `undoNoShow`)
  - undoCheckInBooking (action sœur de ENC-101, voir ses questions ouvertes)
- **Données Prisma** : identique à ENC-101.
- **Services externes** : aucun. UI client uniquement + appel action server.

## Hors-périmètre explicite
- Bouton "Marquer tout présent" en masse (post-MVP).
- Recherche dans la liste (post-MVP, géré par filtre/scroll natif sur ≤ 50 inscrits).
- Action sur sessions passées (read-only).
- Notification au client de son check-in.
- Page dédiée mobile "check-in manuel" (pas besoin, ENC-096 est déjà responsive).

## Métriques de succès
- < 5 % des check-in faits en manuel (le scan reste le mode dominant — au-delà, c'est un signal de problème UX scan).
- 0 incident "check-in irréversible par erreur" remonté en bêta.

## ❓ Questions ouvertes pour Sam
1. **Cohabitation avec ENC-103b sur la même ligne** : on affiche deux boutons "Marquer présent" + "Marquer absent" côte à côte ? Proposition par défaut : **oui, deux boutons distincts** (présent primaire, absent secondaire `ghost`). Alternative : menu kebab unique avec les deux actions.
2. **Fenêtre H-2 / H+4** : tu valides la même fenêtre que le scan, ou plus permissive pour le manuel ? Proposition par défaut : **identique au scan** (cohérence). Alternative : pas de fenêtre temporelle sur le manuel (l'encaveur peut corriger même 3 jours après).
3. **Combo "Annuler no-show + marquer présent"** : action atomique combinée, ou on force l'encaveur à faire deux clics (annuler no-show puis marquer présent) ? Proposition par défaut : **action combinée** (un clic = moins de frustration jour-J).
