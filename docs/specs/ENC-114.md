# ENC-114 — Page encaveur "Reversements" (lecture historique via Stripe API, pas de table custom)

## Objectif métier
L'encaveur reçoit ses paiements par Stripe Connect en rolling balance (versement automatique selon le calendrier configuré sur son compte Connect). Aujourd'hui il doit ouvrir le dashboard Stripe pour comprendre combien il a reçu, quand, et sur quels bookings. On lui offre une vue native dans EnCave qui agrège : date de versement, montant brut, commission EnCave (12 %), montant net reçu, nombre de bookings concernés. **Aucune table custom** : on lit en direct via l'API Stripe `payouts.list` + corrélation avec `BalanceTransaction`. C'est la source de vérité, on ne stocke pas.

## Acteurs
- **WINEMAKER** : depuis son dashboard.

## Préconditions & déclencheurs
- Encaveur authentifié, winery `VERIFIED` avec compte Stripe Connect actif (`stripeAccountId` non null, `chargesEnabled = true`).
- Route : `/[locale]/dashboard/payouts`.
- Accès interdit aux wineries `PENDING` / `SUSPENDED` (pas de compte Connect actif).

## User stories
- En tant qu'**encaveur**, je veux voir l'historique de mes versements EnCave sans quitter la plateforme.
- En tant qu'**encaveur**, je veux comprendre pour chaque versement combien correspond à quels bookings.
- En tant qu'**encaveur**, je veux voir la commission EnCave de manière transparente.
- En tant qu'**encaveur**, je veux filtrer par période (mois courant, 3 derniers mois, année, custom).
- En tant qu'**encaveur**, je veux pouvoir exporter en CSV pour ma comptabilité.

## Règles métier
- **Pas de table `Payout` custom**. Source de vérité = Stripe API.
- Appels Stripe : `stripe.payouts.list({ limit: 100 }, { stripeAccount: winery.stripeAccountId })`.
- Pour le détail d'un payout : `stripe.balanceTransactions.list({ payout: payoutId, expand: ['data.source'] })`.
- Corrélation booking : `metadata.bookingReference` est passé sur chaque PaymentIntent/Charge à la création. On récupère ces métadonnées via les `BalanceTransaction.source` (Charge) puis on lookup les bookings côté DB par référence.
- **Commission EnCave** : 12 % (`PLATFORM_COMMISSION_RATE`). Calcul transparent affiché : `montant_brut - commission = montant_net`. On affiche la commission cumulée par payout (somme des commissions des bookings inclus).
- Format montants : CHF, formatter `formatCHF` (depuis cents).
- Statut payout (Stripe) traduit : `paid` → "Versé", `pending` → "En cours", `in_transit` → "En transit", `failed` → "Échec", `canceled` → "Annulé".
- Cache : `unstable_cache` 5 minutes par `stripeAccountId` pour limiter les appels API. Tag `winery:${id}:payouts` invalidé sur webhook `payout.paid`.
- Pagination : 20 par page, "Voir plus" pour charger 20 supplémentaires (curseur Stripe `starting_after`).
- Filtre période → param `arrival_date[gte]` et `arrival_date[lte]` Stripe.
- Export CSV : généré côté serveur dans un endpoint `/api/dashboard/payouts/export?from=…&to=…`, auth via session.
- Aucune écriture DB côté EnCave dans cette US (lecture seule).

## États UI
- **Loading** : skeleton de 5 lignes de table (Server Component → `loading.tsx`).
- **Empty (jamais de payout)** : illustration + texte explicatif + lien vers FAQ "Comment fonctionnent les versements".
- **Empty (compte Stripe pas prêt)** : carte avec CTA "Finaliser mon compte Stripe" qui ouvre l'onboarding Connect.
- **Error** : bannière + bouton retry, garde la table vide en dessous.
- **Populated** : table desktop / cartes mobile, filtre période en haut à droite, bouton export.

## Cas limites
- Plus de 100 payouts dans la période demandée : pagination par curseur, "Voir plus".
- Payout `failed` : afficher en rouge avec lien "Voir dans Stripe" (vers dashboard Stripe Connect Express de l'encaveur).
- Booking remboursé après un payout : Stripe émet un `BalanceTransaction` de type `refund` qui apparaîtra dans un payout ultérieur (souvent négatif). On reflète tel quel.
- Compte Connect désactivé (`chargesEnabled` repassé à false par Stripe) : on peut quand même montrer l'historique, mais bannière "Ton compte est actuellement inactif".
- Décalage entre Stripe et notre DB (booking supprimé mais payout référence encore son ref) : afficher la référence sans lien, badge "supprimé".
- Devise : EnCave est CHF only. Si un payout Stripe est dans une autre devise (cas improbable), afficher tel quel sans conversion.
- Webhook `payout.paid` raté : pas grave, cache TTL 5min régénère.

## Dépendances
- `getStripe()` depuis `src/server/stripe.ts`.
- Query : `src/server/queries/payouts.queries.ts` avec `listPayoutsForWinery({ stripeAccountId, from, to, cursor })` et `getPayoutDetail(stripeAccountId, payoutId)`.
- Composant : `src/components/features/dashboard/PayoutsTable.tsx` (Server Component) + sous-composants.
- Endpoint export : `src/app/api/dashboard/payouts/export/route.ts`.
- Réutilise : `formatCHF`, `formatDate`, `Booking` ref lookup.
- Permission : middleware existant `requireWineryOwnership`.

## Hors-périmètre explicite
- **Pas de table `Payout`** ni de persistance custom.
- Pas de modification du calendrier de versement (l'encaveur le fait sur Stripe).
- Pas de prévisualisation du prochain payout (Stripe ne l'expose pas proprement).
- Pas de notifications email "vous avez reçu un versement" (Stripe le fait déjà).
- Pas de comptabilité TVA (l'encaveur gère sa fiscalité).
- Pas de support multi-devise.

## Métriques de succès
- > 50 % des encaveurs consultent la page Reversements au moins 1x / mois.
- Réduction du nombre de tickets support "Quand vais-je être payé ?" : objectif -70 %.
- Latence p95 du fetch Stripe < 1.5s grâce au cache.
