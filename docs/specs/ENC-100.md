# ENC-100 — Page `/dashboard/scan` mobile (caméra + html5-qrcode)

## Objectif métier
Permettre à l'encaveur de scanner les QR codes des clients depuis son téléphone (caméra arrière) le jour-J, avec un feedback immédiat à chaque scan. Cible bêta Fondateurs : un encaveur seul, debout, gère 8-15 arrivées en 10 minutes.

## Acteurs
- **WINEMAKER** (acteur unique) : scanne, voit le résultat, scanne le suivant.
- **CLIENT** : présente son QR code (depuis email confirmation ENC-068b ou espace "Mes réservations") — pas d'interaction directe avec cette page.

## Préconditions & déclencheurs
- Encaveur authentifié, winery `VERIFIED`.
- Au moins une session existe avec des bookings `CONFIRMED` accessibles pour le scan (sinon la page reste utilisable mais affiche un état vide).
- Accès depuis le bouton "Scanner les QR codes" de la page détail événement (ENC-096) avec query params `?experienceSlug=...&sessionId=...` (optionnels).
- Navigateur doit supporter `getUserMedia` (caméra). HTTPS obligatoire (Vercel le garantit).

## User stories
- En tant qu'**encaveur**, je veux ouvrir la caméra arrière de mon téléphone et scanner un QR code en moins de 2 secondes, afin d'enchaîner les arrivées sans friction.
- En tant qu'**encaveur**, je veux un retour visuel et sonore clair (vert = OK, rouge = problème), afin de savoir tout de suite si le client est validé.
- En tant qu'**encaveur**, je veux voir quelle session est en cours de scan, afin de ne pas check-in un client sur la mauvaise session.

## Règles métier
- **Format QR** : le QR code contient l'URL `https://encave.ch/b/{accessToken}` (token clair côté client, hashé en DB côté serveur — voir CLAUDE.md "Booking access tokens"). La page scan extrait le token et appelle l'endpoint check-in (ENC-101).
- **Garde-fou session** : si l'URL est appelée avec `sessionId`, on rejette toute tentative de check-in sur un autre `sessionId`. Si pas de `sessionId` fourni, on accepte n'importe quelle session de l'encaveur (mode "scan libre").
- **Garde-fou propriétaire** : le booking doit appartenir à une `Experience.winery.ownerId === session.user.id`. Sinon overlay rouge "Cette réservation n'est pas la vôtre" + log Sentry.
- **Fenêtre temporelle** : scan accepté entre H-2 (avant `session.startsAt`) et H+4 (après `session.endsAt`). Hors fenêtre : overlay orange "Hors fenêtre de check-in" (mais on autorise quand même la transition, c'est un avertissement — confirmation au tap).
- **Anti double-scan** : debounce 1.5s sur le même QR (évite multi-trigger sur une lecture continue).
- **Feedback** : couleur (vert/orange/rouge) + son (configurable, mute par défaut sur certains téléphones) + vibration si supportée (`navigator.vibrate(50)`).
- **Performance** : caméra arrière par défaut (`facingMode: 'environment'`), résolution adaptative html5-qrcode (qrbox 250×250), fps 10.
- **Sécurité** : HTTPS only. Pas de stockage local du token scanné. Token hashé côté serveur avant query DB.

## États UI
- **Loading** : initialisation caméra, spinner centré + texte "Activation de la caméra…".
- **Permission demandée** : écran d'explication + bouton.
- **Permission refusée** : message + bouton réessayer + lien manuel.
- **Scan actif** : viewfinder plein écran, qrbox vert au centre, header avec session active et compteur.
- **Overlay résultat** : full-bleed semi-transparent (vert/orange/rouge) pendant 1.5s puis fade-out, bouton "OK" pour fermer immédiatement.
- **Error (caméra crash, getUserMedia exception)** : message + bouton réessayer + lien manuel.

## Cas limites
- **iOS Safari** : `playsinline` obligatoire sur l'élément vidéo. Tester PWA Safari ≥ 14.
- **Téléphone avec une seule caméra** : `facingMode: 'environment'` peut échouer → fallback `facingMode: 'user'` avec avertissement.
- **Mode paysage** : lock orientation portrait (CSS `screen.orientation.lock('portrait')` ou simple overlay "Tenez votre téléphone vertical").
- **Réseau coupé pendant le scan** : l'appel à l'endpoint check-in échoue → overlay rouge "Réseau indisponible. Réessayez." Le scan continue.
- **Plusieurs scans rapides du même QR** : debounce 1.5s côté client + idempotence côté serveur (ENC-101).
- **Token expiré ou révoqué** : overlay rouge "QR expiré, contactez le client".
- **Page laissée ouverte 20 min** : la caméra reste active (drain batterie). Auto-pause après 5 min d'inactivité (pas de scan) avec bouton "Reprendre".
- **Plusieurs onglets ouverts** : un seul peut utiliser la caméra, second onglet affiche "Caméra utilisée ailleurs".

## Dépendances
- **Autres US** :
  - ENC-096 (point d'entrée, query params)
  - ENC-101 (endpoint server action appelé après chaque scan réussi)
  - ENC-102 (lien de fallback manuel)
  - ENC-068b (génère le QR côté client, format `https://encave.ch/b/{token}`)
- **Données Prisma** :
  - `Booking.accessTokenHash` (lookup via hash du token scanné)
  - `Booking.checkedInAt`, `Booking.status`, `Booking.partySize`, `Booking.sessionId`, `Booking.experienceId`
  - `User.firstName` (affichage overlay succès)
- **Services externes / libs** :
  - `html5-qrcode` (^2.3.x) — ajout au `package.json`
  - `navigator.mediaDevices.getUserMedia`
  - `navigator.vibrate` (optionnel)
  - Web Audio API pour son "ding" (asset audio 50KB max)

## Hors-périmètre explicite
- Scan en mode batch offline (post-MVP).
- Statistiques de scan (combien de tentatives échouées, etc.) — log Sentry suffisant.
- Personnalisation du son.
- Scan multi-événement simultané.
- Lecture de QR autres que ceux d'EnCave (codes-barres produits, etc.).

## Métriques de succès
- Temps moyen entre 2 scans successifs < 3 secondes.
- Taux de succès du scan au premier essai > 95 % (mesuré via Sentry breadcrumbs).
