# ENC-094 — Dashboard mini graph 30j (réservations + remplissage)

## Objectif métier

L'encaveur veut un signal visuel rapide de la santé de son activité sur les 30 derniers jours : "est-ce que ça monte ?", "y a-t-il un creux ?". On ajoute un mini-graph compact sur le dashboard, avec deux courbes : nombre de réservations par jour et taux de remplissage moyen des créneaux du jour. C'est un module **lecture seule, non-interactif** (pas de drill-down dans cette US) — l'objectif est la perception d'une tendance, pas l'analyse fine.

## Acteurs

- **WINEMAKER** : sur son dashboard d'accueil.

## Préconditions & déclencheurs

- Encaveur authentifié, winery `VERIFIED`.
- Route : `/[locale]/dashboard` (carte intégrée au dashboard).
- Fenêtre : **30 jours glissants** se terminant aujourd'hui inclus.
- Si la winery a moins de 7 jours d'historique : on affiche un état "Pas encore assez de données".

## User stories

- En tant qu'**encaveur**, je veux voir d'un coup d'œil l'évolution de mon activité sur 30 jours.
- En tant qu'**encaveur**, je veux comparer le volume de réservations et le remplissage moyen.
- En tant qu'**encaveur**, je veux comprendre rapidement les chiffres clés sans devoir interagir avec le graph.

## Règles métier

- **Période** : 30 jours glissants `[J-29, J]` inclus, timezone `Europe/Zurich`.
- **Courbe 1 — Réservations par jour** : `count(Booking)` groupé par `DATE(createdAt)`, filtré sur `status IN ('CONFIRMED', 'COMPLETED')`. Les `PENDING_PAYMENT` et `CANCELLED_*` sont **exclus** (on veut le signal business net).
- **Courbe 2 — Taux de remplissage moyen** : pour chaque jour où il y a au moins 1 créneau qui démarre (`SessionSlot.startsAt`), on calcule `SUM(bookings confirmés du slot) / SUM(capacity du slot)`. Si pas de créneau ce jour-là, on omet le point (pas de "0 %" trompeur).
- **Tendance** : delta % entre la somme de la période courante et la période précédente de même taille. Calcul sur les réservations (la courbe la plus parlante).
- **Affichage** : sparkline / line chart compact. Pas d'axe X texte verbeux, juste les bornes (date début, "Aujourd'hui").
- **Légende** : deux pastilles colorées avec libellés.
- **Pas d'interactivité avancée** dans cette US : pas de tooltip détaillé au hover, pas de zoom. (À ajouter en P2 si besoin.)
- **Mobile-first** : hauteur ~120px mobile, 180px desktop.
- Cache : `unstable_cache` avec TTL 1h et tag `winery:${id}:stats:30d`, invalidé sur création/confirmation/annulation booking.

## États UI

- **Loading** : skeleton de la carte (rectangle ~180px).
- **Empty (< 7j d'historique)** : carte avec texte "Pas encore assez de données".
- **Empty (0 booking)** : axes vides + texte "Aucune réservation sur cette période".
- **Error** : "Impossible de charger les statistiques." + bouton retry. Ne casse pas le dashboard.
- **Populated** : courbes + KPIs + delta tendance.

Détails visuels (à valider avec Léa) :

- Courbe "Réservations" : couleur primaire EnCave, trait plein 2px.
- Courbe "Remplissage" : couleur secondaire/accent, trait pointillé 2px, échelle 0-100% à droite.
- Pas de remplissage sous la courbe (look propre, pas chargé).

## Cas limites

- Création d'un booking le jour J : impacte immédiatement le point d'aujourd'hui (cache invalidé).
- Booking créé il y a 25 jours mais pour une expérience qui a lieu demain : compté au jour de **création** du booking (signal d'activité commerciale).
- Annulation d'un booking confirmé : le booking sort des comptes (statut change). Tag invalidé.
- Créneau de capacité 0 (rare, anormal) : ignoré dans le calcul du taux.
- DST switch dans la fenêtre : utiliser `localDateToUTC` du projet pour la bucketisation.
- Plus de 200 bookings/jour (cas très improbable MVP) : la query reste performante avec un index sur `(wineryId, createdAt)`.
- Encaveur qui vient de s'inscrire (J0) : empty state.

## Dépendances

- Query : `src/server/queries/dashboard.queries.ts` → `getStats30d(wineryId)` retournant `{ days: [{ date, bookings, fillRate | null }], totals: {…}, previousTotalBookings }`.
- Composant : `src/components/features/dashboard/Stats30dCard.tsx` (Server Component) + `Stats30dChart.tsx` (`'use client'` pour la lib graph).
- Lib graph : laissée à Léa/Nora (suggestion : `recharts` ou `visx`, voire SVG maison pour rester light vu la simplicité du besoin).
- Réutilise : `formatDate`, `Intl.NumberFormat` pour les %.
- Index DB recommandé : `Booking(wineryId, createdAt, status)`.

## Hors-périmètre explicite

- Pas de zoom / drill-down sur un jour spécifique.
- Pas d'export des données.
- Pas de comparaison avec d'autres wineries (benchmark) — sensible.
- Pas de filtrage par expérience.
- Pas d'alerte "ton activité baisse de 30 %".
- Pas de prévisionnel.
- Pas de tooltip détaillé au hover (P2).

## Métriques de succès

- > 60 % des encaveurs scrollent jusqu'à la carte au moins 1x / semaine (instrumentation analytics).
- Latence du fetch < 300ms p95 grâce au cache.

## ❓ Questions ouvertes pour Sam

- **Tutoiement encaveur** (cf. récap général).
- On compte les `COMPLETED` dans la courbe Réservations ? Ma reco : oui, ils sont d'anciens CONFIRMED. Si on les exclut, la courbe chute artificiellement quand les événements ont lieu.
- Pour le taux de remplissage, on agrège par "jour de création du booking" ou "jour de l'événement" (`startsAt`) ? Ma reco : **jour de l'événement** pour le remplissage (= signal opérationnel), **jour de création** pour les réservations (= signal commercial). Confirme.
- Vue par défaut 30j, faut-il offrir 7j / 90j en switch dans le futur ? À noter pour roadmap.
