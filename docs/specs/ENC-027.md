# ENC-027 — Logique visibilité cave publique (critères : KYC ok + photos min + infos complètes + status VERIFIED)

## Objectif métier

Empêcher qu'une cave vide, sans photos, ou non KYCée apparaisse sur le listing public encave.ch. C'est une question de crédibilité plateforme (les 10 Fondateurs sont la vitrine) et de sécurité paiement (pas d'expérience publiée si l'encaveur ne peut pas recevoir les fonds). On définit une notion claire de "cave publiable" et on l'applique partout où une cave est exposée au public.

## Acteurs

- **WINEMAKER** : doit comprendre pourquoi sa cave n'est pas (encore) visible, et savoir quoi compléter.
- **ADMIN** : pilote le statut `VERIFIED`. N'influe pas sur les critères auto.
- **CLIENT** : ne doit voir que des caves complètes et opérables.

## Préconditions & déclencheurs

- L'évaluation `isPubliclyVisible(winery)` est calculée à la volée (dérivée, pas stockée) à chaque listing public, page cave publique, et page détail expérience.
- Déclencheurs UI côté encaveur : bandeau dashboard "Votre cave n'est pas encore visible" listant les critères restants, recalculé à chaque visite du dashboard.

## User stories

- En tant qu'**encaveur**, je veux comprendre à tout moment ce qui me sépare de la mise en ligne publique, pour pouvoir agir.
- En tant que **client**, je ne veux jamais tomber sur une fiche cave incomplète ou une expérience que je ne peux pas réserver.
- En tant qu'**admin**, je veux garder la main sur le statut `VERIFIED` indépendamment des critères techniques.

## Critères d'acceptation (Gherkin)

```gherkin
Fonctionnalité: Visibilité publique d'une cave

Scénario: Cave complète et vérifiée — visible publiquement
  Étant donné une cave avec status=VERIFIED, charges_enabled=true,
    description non vide, ≥ 1 photo, adresse géocodée,
    et ≥ 1 expérience PUBLISHED
  Quand un visiteur charge la page d'accueil ou la page de listing
  Alors la cave apparaît dans les résultats
  Et sa page publique /wineries/{slug} répond en 200

Scénario: Cave PENDING — invisible et page directe en 404
  Étant donné une cave avec status=PENDING
  Quand un visiteur tente d'accéder à /wineries/{slug}
  Alors la page répond avec un 404 i18n
  Et la cave n'apparaît dans aucun listing public

Scénario: Cave VERIFIED mais incomplète — invisible et bandeau encaveur
  Étant donné une cave VERIFIED sans photos
  Quand l'encaveur consulte son dashboard
  Alors un bandeau liste explicitement les critères manquants
  Et la page publique de la cave reste invisible (404)

Scénario: Cave SUSPENDED — masquée immédiatement
  Étant donné une cave précédemment visible passant à SUSPENDED
  Quand on recharge le listing public
  Alors la cave a disparu
  Et /wineries/{slug} renvoie un 404 i18n

Scénario: Encaveur a une expérience DRAFT uniquement
  Étant donné une cave VERIFIED, complète, mais sans expérience PUBLISHED
  Alors la cave reste invisible publiquement
  Et le bandeau dashboard mentionne "Publiez au moins une expérience"
```

## Règles métier

**Critères cumulatifs `isPubliclyVisible(winery) = true`** :

1. `winery.status === 'VERIFIED'`
2. `winery.stripeAccount.charges_enabled === true` (proxy KYC — ENC-032b ajoutera `kycStatus` explicite plus tard, refacto trivial)
3. `winery.photos.length >= 1` (photo de couverture comprise)
4. `winery.description` non vide après strip tags + trim (≥ 1 caractère)
5. `winery.address.latitude !== null && winery.address.longitude !== null` (adresse géocodée Nominatim)
6. `winery.experiences.some(e => e.status === 'PUBLISHED')` (≥ 1 expérience publiée)

**Comportement quand non-visible** :

- Listings publics (`/`, `/wineries`, `/experiences`) : la cave est filtrée — invisible.
- Page directe `/wineries/{slug}` : **404 i18n** (pas de "bientôt disponible" qui leakerait l'existence d'un brouillon).
- Page expérience `/experiences/{experienceSlug}` : 404 si la cave parente n'est pas visible, même si l'expérience est `PUBLISHED` (route flat, pas nestée sous la cave).
- Lien de preview interne (ENC-029, hors scope) : reste accessible à l'encaveur connecté.

**Recalcul** :

- Pas de champ DB `isPubliclyVisible` — c'est une fonction dérivée. Évite la désynchronisation et les jobs de recalcul.
- Implémenter `isWineryPubliclyVisible(winery)` dans `src/lib/business-rules/winery-visibility.ts`. Réutilisé par queries publiques + dashboard encaveur.

**Cache** :

- Les queries publiques filtrent au niveau SQL où possible (status, charges_enabled, count photos, count experiences). Le check description non vide et géocodage se fait dans le `where` Prisma aussi.
- Invalidation : `revalidateTag('winery:{id}')` sur édition profil cave, ajout photo, publication expérience, changement statut.

## États UI

- **Loading** : skeleton du bandeau dashboard pendant le fetch.
- **Empty** : aucun critère validé → bandeau "Bienvenue, commençons" + liste complète des 6 critères.
- **Error** : si la fonction de calcul échoue (timeout Stripe), on considère KYC non rempli (fail-closed) et on logge via `logError`.
- **Populated (partiel)** : bandeau orange, critères cochés/non-cochés visibles.
- **Populated (complet)** : bandeau vert "Votre cave est en ligne" + lien vers la page publique.

## Cas limites

- **Cave VERIFIED qui perd `charges_enabled`** (KYC obsolète Stripe) : devient invisible immédiatement au prochain check. Aucun nouveau booking possible. Bookings existants : non impactés (hors scope ici).
- **Encaveur supprime sa dernière photo** : cave masquée au prochain rendu. Expériences `PUBLISHED` deviennent inaccessibles publiquement (404) mais restent `PUBLISHED` en DB.
- **Cave SUSPENDED par admin** : masquée même si tous les critères techniques sont remplis. Même comportement public que `PENDING` → 404 i18n dur, pas de message dédié.
- **Description en HTML** : strip tags + trim avant de vérifier qu'il reste au moins 1 caractère.
- **Photo de couverture seule** : compte pour 1, donc suffit.
- **Adresse saisie mais géocodage Nominatim échoué** : cave invisible. Bandeau "Adresse non géocodée, vérifiez la saisie".
- **Expérience `PUBLISHED` mais cave non visible** : la page expérience renvoie 404, même si l'expérience est techniquement valide.

## Dépendances

- ENC-032b (champ `kycStatus` explicite) — viendra remplacer le proxy `charges_enabled`, refacto isolé.
- Système de photos cave (existe).
- Géocodage Nominatim (existe).
- Statut `VERIFIED` géré par admin (existe).

## Hors-périmètre explicite

- Page preview interne `/wineries/{slug}?preview=1` pour l'encaveur connecté → autre US.
- Notifications email automatiques quand un critère bascule.
- Score qualité visuel ("Profil rempli à 60%").
- Configuration admin de seuils min (description, photos) — fixés en dur dans le code pour l'instant.

## Métriques de succès

- 100% des caves listées publiquement remplissent les 6 critères (audit hebdo).
- 0 réclamation client type "j'ai voulu réserver mais l'encaveur ne peut pas être payé".
- Délai médian "VERIFIED → publiquement visible" parmi les Fondateurs.

## Décisions Sam (2026-05-13)

1. **Seuil description** : pas de seuil de longueur. La description doit juste être non vide (≥ 1 caractère après strip tags + trim).
2. **Seuil photos** : ≥ 1 photo minimum (revu à la baisse depuis la proposition initiale à 3).
3. **Page `/wineries/{slug}` quand cave non visible** : **404 i18n dur**. On ne distingue pas le cas brouillon vs cave inexistante (neutre SEO, pas de leak d'existence).
4. **Cave `SUSPENDED`** : même traitement public que `PENDING` → 404 i18n dur, pas de message dédié.
5. **Paths URL** : on s'aligne sur l'existant `/wineries/[slug]` (terminologie métier "cave" conservée en FR, mais routes en anglais). Page détail expérience reste à `/experiences/[slug]` (route flat, pas nestée sous la cave).
