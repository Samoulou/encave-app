# ENC-025 — Étape onboarding "premier événement" (skippable)

## Objectif métier

Une fois le KYC Stripe terminé, l'encaveur est laissé devant un dashboard vide. Le risque : il ferme l'onglet, repousse la création d'expérience à "plus tard", et on perd l'élan. Cette étape onboarding pousse explicitement vers la création de la première expérience, juste après le KYC, tout en restant skippable (certains Fondateurs préfèrent finir leur profil cave d'abord). Le but : maximiser le taux de caves avec ≥ 1 expérience publiée à J+7 du signup.

## Acteurs

- **WINEMAKER** fraîchement KYCé.

## Préconditions & déclencheurs

- L'étape s'affiche après le retour de Stripe Connect (callback `charges_enabled = true`) **et** au moins une fois après chaque login tant que la cave n'a pas d'expérience (`DRAFT` ou `PUBLISHED`).
- Vit dans le flow onboarding existant (route `/onboarding/...`) en tant qu'étape suivante de KYC.

## User stories

- En tant qu'**encaveur** qui vient de finir mon KYC, je veux être guidé immédiatement vers la création de ma première expérience.
- En tant qu'**encaveur**, je veux pouvoir reporter cette étape si je n'ai pas le temps ou les infos sous la main.
- En tant qu'**encaveur** qui a skippé, je veux être rappelé doucement à le faire depuis mon dashboard.

## Règles métier

**Statut étape onboarding** :

- Champ `firstExperienceStepSkippedAt: DateTime?` sur `User` ou `Winery` (recommandation : `Winery`, c'est un attribut de la cave).
- L'étape est "complétée" si `winery.experiences.length > 0` (peu importe le statut). On ne crée pas un statut dédié.
- L'étape est "skippable" si l'encaveur clique "Plus tard" → on set `firstExperienceStepSkippedAt = now()`.

**Logique d'affichage** :

- Après callback Stripe Connect réussi → redirect server-side vers `/onboarding/first-experience` (et pas direct dashboard).
- Si l'encaveur a déjà une expérience → redirect `/dashboard`.
- Si `firstExperienceStepSkippedAt` est set ET pas d'expérience → on n'oblige pas le passage par l'étape onboarding au login suivant (juste le bandeau dashboard).

**Bandeau dashboard "nudge"** :

- Visible tant que `winery.experiences.length === 0`.
- Disparaît dès qu'une expérience existe (même `DRAFT`).
- Ton encourageant, pas culpabilisant. CTA direct vers création.

**Contenu de l'écran onboarding** :

- Titre, sous-titre rassurant ("ça prend 10 minutes"), illustration ou screenshot d'un exemple d'expérience publiée, 3 bullets de réassurance (vous pouvez modifier plus tard, vous pouvez la garder en brouillon, on est là si question), 2 CTA.

## États UI

- **Loading** : skeleton léger pendant la vérification "a-t-il déjà une expérience ?".
- **Empty** : c'est l'état nominal (par définition, pas d'expérience à ce stade).
- **Error** : si la query échoue, on laisse passer vers dashboard avec bandeau (fail-open, l'encaveur n'est pas bloqué).
- **Populated** : si l'encaveur a déjà une expérience → redirect automatique vers `/dashboard`.

## Cas limites

- **Encaveur skip puis crée une expérience** : le bandeau disparaît automatiquement (dérivé de `experiences.length`).
- **Encaveur skip plusieurs fois (en revenant manuellement sur l'URL)** : on update `firstExperienceStepSkippedAt` à chaque skip → on garde le timestamp le plus récent.
- **Encaveur supprime sa seule expérience (passe de 1 à 0)** : le bandeau réapparaît. Pas de re-redirection forcée.
- **Encaveur dont KYC est terminé mais qui n'a jamais vu cette étape** (ex. migration de comptes pré-existants) : à son prochain login, redirect une seule fois vers `/onboarding/first-experience`. Après skip, comportement normal.
- **Encaveur quitte le formulaire de création à mi-chemin** : retour dashboard, bandeau persiste, le brouillon est-il sauvegardé ? → décision côté ENC-026b / création expérience, hors scope ici.
- **Cave SUSPENDED par admin** : pas de redirect onboarding, accès dashboard normal avec message admin.

## Dépendances

- Callback KYC Stripe Connect (existe).
- Formulaire création expérience `/dashboard/experiences/new` (existe).
- Champ `firstExperienceStepSkippedAt` à ajouter sur `Winery` (migration Prisma).

## Hors-périmètre explicite

- Modèles pré-remplis d'expériences ("Dégustation classique 1h", "Visite de cave 1h30") — à spécifier en US séparée.
- Wizard multi-étapes pour créer l'expérience (on envoie sur le formulaire normal).
- Email de relance J+1, J+3 si pas d'expérience créée (cf. ENC-035 esprit similaire pour KYC, à dupliquer plus tard).
- Gamification (progression %, badges).

## Métriques de succès

- 80% des encaveurs qui terminent leur KYC créent une expérience (DRAFT ou PUBLISHED) sous 24h.
- Taux de skip < 30%.
- Délai médian "KYC terminé → première expérience PUBLISHED" < 48h.

## ❓ Questions ouvertes pour Sam

1. **Skip silencieux ou skip avec raison ?** Recommandation Théo : skip silencieux MVP (un seul clic). Plus tard on pourra demander pourquoi (manque de temps, pas prêt, etc.) si utile pour l'analyse.
2. **Bandeau dashboard persistant** : tant qu'il n'y a pas d'expérience, ok. Mais faut-il un bouton "Masquer ce bandeau" ? Recommandation : non, sinon l'encaveur le masque et n'agit jamais.
3. **Position du `firstExperienceStepSkippedAt`** : sur `Winery` (recommandation) ou sur `User` ? Si on prévoit la multi-membres post-MVP, `Winery` est plus cohérent.
4. **Templates d'expériences pré-remplis** : on planifie une US dédiée ou pas du tout MVP ? Les Fondateurs apprécieraient probablement.
