# ENC-035 — Email relance KYC J+1 si onboarding Stripe pas commencé

## Objectif métier

Un encaveur qui ne complète pas son onboarding Stripe Connect ne peut pas recevoir d'argent — donc ne peut pas publier d'expérience. Aujourd'hui, sans relance, beaucoup oublient ou repoussent. Une relance email à J+1 ré-active les comptes dormants et améliore le taux d'activation Fondateurs (cible : > 80 % en 7 jours).

## Acteurs

- **WINEMAKER** : reçoit la relance.
- **SYSTEM (cron J+1)** : déclencheur.
- **ADMIN** : surveille le funnel.

## Préconditions & déclencheurs

- Cron Vercel **quotidien** à **10h00 Europe/Zurich** (`0 8 * * *` UTC, ajustable DST).
- Authentifié via `CRON_SECRET`.
- Cible : wineries dont le compte Stripe Connect a été créé entre 24h et 48h avant le run, dont `details_submitted=false` côté Stripe, et qui n'ont **pas encore reçu** la relance KYC.

## User stories

- En tant qu'**encaveur**, si j'ai oublié de finir mon inscription Stripe, je veux un coup de pouce poli pour terminer sans avoir à fouiller dans mes emails.
- En tant que **plateforme**, je veux maximiser le taux d'activation Stripe sans spammer.

## Critères d'acceptation (Gherkin)

```gherkin

  Étant donné un encaveur dont le compte Stripe Connect a été créé il y a 25h
  Et dont Stripe Account.details_submitted = false
  Et dont Winery.kycReminderSentAt est null
  Quand le cron /api/cron/kyc-reminder s'exécute
  Alors un email "Finalisez votre inscription EnCave" est envoyé à l'encaveur
  Et Winery.kycReminderSentAt = now()
  Et un événement est loggé winery.kyc.reminder.sent

Scénario : pas de relance si onboarding démarré
  Étant donné un encaveur avec details_submitted = true
  Quand le cron s'exécute
  Alors aucun email n'est envoyé

Scénario : pas de double relance
  Étant donné un encaveur déjà relancé (kycReminderSentAt non null)
  Quand le cron s'exécute
  Alors aucun email n'est envoyé même si details_submitted reste false

Scénario : trop tôt
  Étant donné un encaveur dont le compte Stripe a été créé il y a 8h
  Quand le cron s'exécute
  Alors aucun email n'est envoyé (fenêtre 24h-48h non atteinte)

Scénario : trop tard
  Étant donné un encaveur dont le compte Stripe a été créé il y a 5 jours sans relance envoyée
  Quand le cron s'exécute
  Alors aucun email n'est envoyé (fenêtre 24h-48h dépassée)
  Et un warn est loggé "kyc.reminder.window.missed" pour ce winery

Scénario : authentification
  Quand /api/cron/kyc-reminder reçoit une requête sans CRON_SECRET valide
  Alors le endpoint répond 401
```

## Règles métier

- **Fenêtre déclenchement** : `stripeAccountCreatedAt` ∈ `[now - 48h, now - 24h]`. Strictement 1 fois par winery.
- **Lecture Stripe** : `stripe.accounts.retrieve(stripeAccountId)` pour récupérer `details_submitted`. Si l'appel échoue (Stripe down), skipper ce winery + log warn, retry au prochain run (mais la fenêtre peut être manquée — c'est OK, on accepte la perte).
- **Persistance** : ajouter `kycReminderSentAt: DateTime?` sur `Winery`. Migration Prisma.
- **Anti-spam** : **1 seul email**. Pas de J+3, pas de J+7 (à V2 si besoin, après mesure).
- **Pas de relance** si :
  - Compte Stripe inexistant (encaveur n'a pas commencé du tout — ce serait une autre US, ENC-036 potentielle).
  - Winery.status = `REJECTED` ou `SUSPENDED`.
  - `kycReminderSentAt` déjà rempli.
- **CTA email** → lien direct vers la reprise du flow Stripe Onboarding (génère un nouveau Account Link via `stripe.accountLinks.create` au moment du clic, type `account_onboarding`).
- **Lien dans l'email = lien EnCave** (`https://encave.ch/dashboard/onboarding/stripe-resume`), pas directement un Account Link Stripe (les Account Links expirent vite).
- **Logging** : `logInfo('winery.kyc.reminder.sent', { wineryId, daysSinceAccountCreation })`.
- **Idempotence** : champ `kycReminderSentAt` garantit no-op si rerun le même jour.

## États UI

- **Loading** : N/A (cron).
- **Empty** : run sans cible → réponse `{ remindersSent: 0 }`.
- **Error** : par-winery try/catch. Erreur Stripe → skip + log. Erreur Resend → marquer reminder NON envoyé (ne pas remplir `kycReminderSentAt`) pour retenter au prochain run dans la fenêtre.
- **Populated** : réponse JSON `{ remindersSent: N, skipped: M }`.

Côté encaveur, page `/dashboard/onboarding/stripe-resume` :

- **Loading** : skeleton.
- **Empty** : N/A (toujours un compte).
- **Error** : "Impossible de régénérer le lien Stripe. Réessayez ou contactez le support."
- **Populated** : auto-redirect vers l'URL Stripe Account Link fraîchement créée.

## Cas limites

- Encaveur qui clique sur le CTA après expiration de l'Account Link Stripe : la page `/stripe-resume` en génère un nouveau à chaque clic.
- Encaveur qui finalise Stripe entre 2 runs : capté au run suivant (details_submitted=true → skip).
- Cron qui tourne pendant un downtime Stripe : on log warn, on n'envoie pas, on rate la relance pour ce jour-là (acceptable).
- Encaveur avec adresse email invalide (bounce) : Resend retournera l'erreur, log + capture Sentry, on **remplit quand même** `kycReminderSentAt` (sinon on retentera en boucle).
- Multi-runs accidentels du cron le même jour : `kycReminderSentAt` déjà rempli → skip.

## Dépendances

- Migration Prisma : `Winery.kycReminderSentAt: DateTime?`.
- Endpoint cron : `src/app/api/cron/kyc-reminder/route.ts`.
- `vercel.json` : entrée cron quotidienne 10h Europe/Zurich.
- Email template : `KycReminderEmail` (React Email, nouveau).
- Page : `/dashboard/onboarding/stripe-resume` (server component qui appelle `stripe.accountLinks.create` et redirect).
- Pas de dépendance bloquante avec ENC-030b / autres.

## Hors-périmètre explicite

- Pas de J+3, J+7, ou relances multiples — explicitement 1 seul email.
- Pas de SMS.
- Pas de relance pour KYC commencé mais pas fini (en cours de soumission Stripe).
- Pas de relance admin "untel n'a toujours pas activé" (V2 dashboard ops).
- Pas de gestion fine des étapes manquantes spécifiques (ex : "il manque votre IBAN") — Stripe gère son propre wording dans le flow.

## Métriques de succès

- Taux d'activation Stripe à J+7 > 80 % (vs baseline à mesurer avant rollout).
- Taux d'ouverture email > 50 % (transactionnel avec sujet personnalisé).
- Taux de clic CTA > 30 %.
- 0 plainte "j'ai été spammé".
