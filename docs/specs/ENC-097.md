# ENC-097 — Action mailto: groupé sur page détail événement (contacter tous les inscrits)

## Objectif métier

L'encaveur a régulièrement besoin de contacter en groupe les inscrits d'un créneau (changement météo, info parking, retard d'un fournisseur, photo de groupe à proposer après l'événement). Aujourd'hui il doit copier-coller les emails un par un. On lui fournit un bouton qui ouvre son client mail avec tous les inscrits en **BCC** (pour préserver la vie privée) et un sujet pré-rempli. C'est volontairement low-tech : pas de système d'emailing interne dans cette US (qui viendra plus tard avec templates, tracking, etc.).

## Acteurs

- **WINEMAKER** : depuis la page détail d'un créneau dans son dashboard.

## Préconditions & déclencheurs

- Encaveur authentifié, propriétaire de la winery.
- Route : `/[locale]/dashboard/experiences/{slug}/slots/{slotId}` (page détail créneau).
- Au moins 1 booking `CONFIRMED` rattaché au créneau.
- L'encaveur a un client mail configuré sur son appareil (sinon l'URL `mailto:` ouvre une fenêtre de sélection ou ne fait rien : on ne peut pas le gérer).

## User stories

- En tant qu'**encaveur**, je veux envoyer un email à tous les inscrits d'un créneau en 1 clic.
- En tant qu'**encaveur**, je veux que les destinataires ne voient pas les emails des autres inscrits.
- En tant qu'**encaveur**, je veux un sujet pré-rempli avec le nom de l'événement et la date pour ne pas avoir à le retaper.
- En tant que **client inscrit**, je veux que mon email ne soit pas partagé avec les autres clients.

## Critères d'acceptation (Gherkin)

```gherkin
Scénario : envoi groupé sur un créneau avec inscrits
  Étant donné un créneau avec 5 bookings CONFIRMED (5 emails uniques)
  Quand l'encaveur clique sur "Contacter tous les inscrits"
  Alors un lien mailto: s'ouvre avec :
    - to: vide (ou l'email de l'encaveur)
    - bcc: les 5 emails séparés par virgule
    - subject: pré-rempli avec titre événement + date
    - body: vide ou template court personnalisable plus tard

Scénario : créneau sans inscrits
  Étant donné un créneau sans booking CONFIRMED
  Quand l'encaveur consulte la page détail
  Alors le bouton "Contacter tous les inscrits" est désactivé (grisé)
  Et un tooltip indique "Aucun inscrit à contacter pour le moment."

Scénario : dépassement de la limite mailto:
  Étant donné un créneau avec un nombre d'inscrits dont l'URL mailto résultante > 1800 caractères
  Quand l'encaveur clique sur le bouton
  Alors une modale "fallback" s'ouvre proposant de copier la liste d'emails dans le presse-papier
  Et un message explicite "Trop d'inscrits pour ouvrir ton client mail directement. Copie la liste ci-dessous dans le BCC manuellement."

Scénario : copie presse-papier (fallback)
  Quand l'encaveur utilise le fallback "Copier les emails"
  Alors les emails sont copiés au format "email1@x.ch, email2@x.ch, …"
  Et un toast confirme "Emails copiés. Colle-les dans le BCC de ton mail."

Scénario : bookings annulés exclus
  Étant donné un créneau avec 3 CONFIRMED et 2 CANCELLED_BY_CLIENT
  Quand l'encaveur clique sur le bouton
  Alors seuls les 3 CONFIRMED sont inclus dans le BCC

Scénario : sécurité — autre encaveur
  Étant donné un encaveur A et un créneau qui appartient à l'encaveur B
  Quand A tente d'accéder à la page ou au lien
  Alors la route renvoie 404 (pas 403, pour ne pas leaker l'existence)
```

## Règles métier

- **BCC obligatoire**, jamais To ni Cc. Le `To` peut être l'email de l'encaveur lui-même (utile car certains clients mail refusent un mailto sans To).
- Emails inclus : `Booking.email` pour `status = CONFIRMED` uniquement. On exclut `PENDING_PAYMENT`, `CANCELLED_*`, `NO_SHOW`. `COMPLETED` est inclus uniquement si on est dans les 48h post-événement (cas "merci/photos"), à valider.
- Déduplication : si un même email apparaît sur plusieurs bookings du même créneau, on l'inclut une seule fois.
- Limite URL mailto : seuil safe **1800 caractères** sur la chaîne totale (certains clients tronquent à 2000+). Au-delà → fallback copy-paste.
- Sujet pré-rempli : `[EnCave] {experienceTitle} — {dateFR}`.
- Body : **vide** dans cette US (ou template ultra-court "Bonjour, … L'équipe {winery}"). Décision Sam.
- Tracking : pas de tracking d'ouverture (on n'envoie pas l'email, c'est le mail client de l'encaveur qui le fait).
- L'action est **côté client uniquement** (génération du lien `mailto:`). Pas de server action.
- Les emails ne doivent JAMAIS être exposés en clair dans le HTML rendu. Récupération via une server action `getAttendeeEmailsForSlot(slotId)` qui re-vérifie l'ownership, déclenchée au clic du bouton.

## États UI

- **Loading** : bouton en `isPending` pendant la récup serveur des emails (très court, ~200ms).
- **Empty** : bouton désactivé + tooltip.
- **Error** : toast d'erreur "Impossible de récupérer la liste. Réessaie." si la server action fail.
- **Populated** : bouton actif, ouverture immédiate du `mailto:` ou de la modale fallback selon longueur.

## Cas limites

- Email invalide en DB (corruption rare) : exclu silencieusement, log warn.
- Encaveur clique pendant qu'un booking se fait annuler (course condition) : on prend le snapshot au moment du clic, c'est OK.
- Client mail non configuré sur l'appareil : on ne peut pas le détecter. Conseil dans la modale RGPD : "Si rien ne s'ouvre, utilise le bouton 'Copier la liste'."
- Encaveur sur mobile : `mailto:` ouvre le client mail natif. Sur iOS, BCC est bien supporté.
- Emails contenant des caractères spéciaux : URL-encoder via `encodeURIComponent`.
- Plus de 30 inscrits : très probablement on dépasse le seuil → fallback systématique au-delà.

## Dépendances

- Server action : `getAttendeeEmailsForSlot(slotId)` dans `src/server/actions/bookings/getAttendeeEmails.ts`. Vérif ownership + retourne `string[]`.
- Composant : `src/components/features/dashboard/ContactAttendeesButton.tsx` (`'use client'`).
- Modale fallback : réutiliser le `Dialog` shadcn.
- Utilitaire : `buildMailtoLink({ to, bcc, subject, body })` dans `src/lib/utils/mailto.ts`.

## Hors-périmètre explicite

- Pas de système d'emailing interne (templates, tracking, désabonnement) — c'est volontairement low-tech.
- Pas de segmentation (ex. "contacter seulement les anglophones") dans cette US.
- Pas de planification d'envoi.
- Pas de SMS, pas de WhatsApp.
- Pas de gestion des bounces.
- Pas d'historique des messages envoyés.

## Métriques de succès

- Adoption : > 30 % des encaveurs ont utilisé l'action au moins 1 fois après 1 mois.
- 0 plainte client liée à un email fuité (validation BCC).
