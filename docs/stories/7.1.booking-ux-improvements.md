# Story 7.1: Booking UX Improvements

## Status

Done

## Story

**As a** visitor booking an experience,
**I want** a clear and consistent booking interface,
**so that** I can easily understand availability and complete my reservation without confusion.

## Bugs Addressed

| Bug ID | Severity | Description |
|--------|----------|-------------|
| BUG-030 | P1 | URL state: time slot removed from URL when changing date |
| BUG-031 | P2 | Duplicate remaining capacity display (text + badge) |
| BUG-032 | P2 | Confusing capacity text "8-10 10 personnes" |
| BUG-033 | P1 | Calendar left arrow appearing on right side of page |

## Acceptance Criteria

1. When changing the selected date, the time slot selection persists in the URL if the same time is still available on the new date
2. Remaining capacity is displayed ONLY as a badge (not duplicated as text + badge)
3. Capacity text in experience header card displays clearly (e.g., "8-10 personnes" not "8-10 10 personnes")
4. Calendar navigation arrows appear only in their correct positions (left arrow on left, right arrow on right)
5. No visual glitches or duplicate UI elements in the booking flow

## Technical Details

### BUG-030: Time Slot URL State Not Persisting

**File:** `src/components/features/booking/BookingWidget.tsx:49-55`

**Problem:**
```typescript
const handleDateChange = useCallback(
  (newDate: string | null) => {
    setQueryState({ date: newDate, time: null }); // <-- time explicitly set to null!
    setRemainingCapacity(null);
  },
  [setQueryState]
);
```

When changing the date, `time` is always reset to `null`, removing it from the URL.

**Fix Required:**
1. Keep `time` value when date changes
2. Only clear `time` if it's no longer available on the new date (validate after date change)
3. Alternative: Keep time in URL but let TimeSlotSelector handle validation

**UX Improvement:**
```typescript
const handleDateChange = useCallback(
  (newDate: string | null) => {
    // Keep time selection - TimeSlotSelector will validate if still available
    setQueryState({ date: newDate });
    setRemainingCapacity(null);
  },
  [setQueryState]
);
```

### BUG-031: Duplicate Remaining Capacity Display

**File:** `src/components/features/booking/GuestCountInput.tsx:118-138`

**Problem:**
Remaining capacity is displayed TWICE when `remainingCapacity <= 3`:

1. **Text display (line 118-125):**
```tsx
{remainingCapacity !== null ? (
  <span className={cn(remainingCapacity <= 3 ? 'text-orange-600 font-medium' : '')}>
    {t('remainingCapacity', { count: remainingCapacity })}
  </span>
) : (
  <span>{t('maxGuests', { count: max })}</span>
)}
```

2. **Badge display (line 132-138):**
```tsx
{remainingCapacity !== null && remainingCapacity <= 3 && remainingCapacity > 0 && (
  <div className="flex justify-center">
    <span className="inline-flex items-center rounded-full bg-orange-100 px-3 py-1 text-xs font-medium text-orange-800">
      {t('remainingCapacity', { count: remainingCapacity })}
    </span>
  </div>
)}
```

Both show the SAME text when capacity is low.

**Fix Required:**
Remove the text display when capacity is low, keep only the badge:

```tsx
{/* Capacity Info */}
<div className="flex items-center justify-center gap-4 text-sm text-slate-500">
  <span>{t('minGuests', { count: min })}</span>
  <span className="text-slate-300">|</span>
  {isLoading ? (
    <span className="flex items-center gap-1">
      <Loader2 className="h-3 w-3 animate-spin" />
      Loading...
    </span>
  ) : remainingCapacity !== null && remainingCapacity > 3 ? (
    // Only show text when NOT low capacity
    <span>{t('remainingCapacity', { count: remainingCapacity })}</span>
  ) : remainingCapacity === null ? (
    <span>{t('maxGuests', { count: max })}</span>
  ) : null}
</div>

{/* Badge for low capacity - this is the only display when <= 3 */}
{remainingCapacity !== null && remainingCapacity <= 3 && remainingCapacity > 0 && (
  <div className="flex justify-center">
    <span className="inline-flex items-center rounded-full bg-orange-100 px-3 py-1 text-xs font-medium text-orange-800">
      {t('remainingCapacity', { count: remainingCapacity })}
    </span>
  </div>
)}
```

### BUG-032: Confusing Capacity Text "8-10 10 personnes"

**File:** `src/components/features/booking/BookingWidget.tsx:127`

**Problem:**
```tsx
<span className="flex items-center gap-1.5">
  <Users className="h-4 w-4" />
  {experience.minCapacity}-{experience.maxCapacity} {t('guests', { count: experience.maxCapacity })}
</span>
```

Output: `8-10 10 personnes` - The number appears twice (once in the range, once from the translation).

**Fix Required:**
Use a dedicated translation key that accepts min and max:

```tsx
<span className="flex items-center gap-1.5">
  <Users className="h-4 w-4" />
  {t('capacityRange', { min: experience.minCapacity, max: experience.maxCapacity })}
</span>
```

**New translation keys:**
```json
// en.json
"capacityRange": "{min}-{max} guests"

// fr.json
"capacityRange": "{min}-{max} personnes"

// de.json
"capacityRange": "{min}-{max} Gäste"
```

### BUG-033: Calendar Left Arrow on Right Side

**File:** `src/components/features/booking/BookingDatePicker.tsx:91-92` + potential global CSS issue

**Current Styling:**
```tsx
nav_button_previous: 'absolute left-1',
nav_button_next: 'absolute right-1',
```

**Potential Causes:**
1. CSS specificity conflict with global styles
2. react-day-picker version issue with icon rendering
3. Parent container CSS affecting absolute positioning
4. Possible duplicate icon import or rendering

**Investigation Required:**
1. Check Calendar component from `@/components/ui/calendar`
2. Inspect browser DevTools for CSS conflicts
3. Verify lucide-react icons are correct (ChevronLeft vs ChevronRight)
4. Check for duplicate nav button rendering

**Likely Fix:**
Add explicit `right-auto` to previous button and `left-auto` to next button:

```tsx
nav_button_previous: 'absolute left-1 right-auto',
nav_button_next: 'absolute right-1 left-auto',
```
