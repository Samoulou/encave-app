# Story 12.1: Homepage Enhancements & Public Navigation Fixes

## Status

Draft

## Story

**As a** visitor landing on the homepage,
**I want** an engaging visual design with functional navigation elements,
**so that** I can quickly understand the value proposition and navigate to key actions (search, register, login, become partner).

## Problem Statement

User feedback identified 5 critical issues on the homepage:

1. **Missing Visual Impact**: No background image - page feels flat and uninspiring
2. **No Quick Search**: Users cannot search for experiences directly from homepage
3. **Broken CTA**: "Become partner" button does nothing when clicked
4. **Auth Navigation Broken**: /register and /login routes not working
5. **Header Buttons Broken**: Connection and register buttons in header non-functional

## Acceptance Criteria

### AC1: Hero Section with Background Image
1. Homepage displays a hero section with wine-related background image
2. Image is optimized (WebP format, responsive srcset)
3. Text overlay has proper contrast for readability
4. Image loads lazily for performance
5. Fallback gradient if image fails to load

### AC2: Quick Event Search
1. Search input field prominently displayed on homepage hero
2. Search triggers navigation to `/experiences?q={searchTerm}`
3. Placeholder text guides user (e.g., "Search wine experiences...")
4. Search works with Enter key and search button
5. Search input is accessible (label, aria attributes)

### AC3: "Become Partner" Button
1. Button navigates to `/register?role=winemaker` or equivalent
2. If auth exists, redirect to dashboard with upgrade prompt
3. Button has proper hover/focus states
4. Button works on both mobile and desktop

### AC4: Auth Routes Fix
1. `/login` route renders login page correctly
2. `/register` route renders registration page correctly
3. Routes include locale prefix (e.g., `/fr/login`)
4. Proper 404 handling if routes misconfigured

### AC5: Header Auth Buttons
1. "Connexion" button navigates to `/login`
2. "S'inscrire" button navigates to `/register`
3. Buttons use proper locale-prefixed URLs
4. Buttons show loading state during navigation

## Technical Investigation Required
