# Story 6.1: Fix Critical Booking Flow Bugs

## Status

In Progress (Revisions Required)

## Story

**As a** visitor booking an experience,
**I want** the booking widget to work reliably,
**so that** I can complete my reservation without errors or confusion.

## Bugs Addressed

| Bug ID | Severity | Description |
|--------|----------|-------------|
| BUG-001 | P0 | Guest count infinite loading after selecting date/time |
| BUG-002 | P0 | +/- guests buttons not working |
| BUG-003 | P0 | No capacity validation before payment |
| BUG-003b | P0 | **NEW** - Continue button not disabled when capacity exceeded on booking page |
| BUG-013 | P1 | No availability recheck on checkout page load |
| BUG-023 | P2 | Stale closure in BookingWidget guest state |
| BUG-029 | P1 | **NEW** - Booking confirmation email not sending |

## Acceptance Criteria

1. When selecting date and time, guest count loading completes within 3 seconds or shows error
2. If availability check fails, user sees clear error message with retry option
3. Guest +/- buttons respond immediately to clicks without race conditions
4. Guest count respects remaining capacity in real-time
5. Checkout page validates availability on mount before showing form
6. If capacity is exceeded during checkout, user is redirected back with clear message
7. User cannot proceed to payment if requested guests > available capacity
8. Form state properly resets when experience or date changes
9. **NEW**: "Continue to payment" button is disabled on booking page when `guests > remainingCapacity`
10. **NEW**: User sees clear message explaining why they cannot continue (e.g., "Only X spots remaining")
11. **NEW**: Booking confirmation email is sent to visitor after successful payment
12. **NEW**: Winemaker notification email is sent after successful booking

## Technical Details

### BUG-001: Guest Count Infinite Loading

**File:** `src/components/features/booking/BookingWidget.tsx:70-86`

**Problem:**
```typescript
useEffect(() => {
  if (date && time) {
    setIsLoadingCapacity(true);
    import('@/server/actions/booking').then(({ checkAvailability }) => {
      checkAvailability({...}).then((result) => {
        if (result.success) {
          setRemainingCapacity(result.data.remainingCapacity);
        }
        setIsLoadingCapacity(false);
      });
      // NO CATCH - if error, loading stays true forever
    });
  }
}, [date, time, experience.id]);
```

**Fix Required:**
1. Add `.catch()` handler to set `isLoadingCapacity = false` on error
2. Add timeout (5s) to prevent indefinite loading
3. Show error state with retry button
4. Move dynamic import to top of file

### BUG-002: +/- Buttons Not Working

**Files:**
- `src/components/features/booking/GuestCountInput.tsx:39-41`
- `src/components/features/booking/BookingWidget.tsx:201`

**Problem:**
Race condition between async capacity fetch and button state updates. When `remainingCapacity` updates during click, button becomes disabled mid-interaction.

**Fix Required:**
1. Debounce capacity updates to prevent mid-click state changes
2. Use `useTransition` for capacity state updates
3. Ensure `onChange` callback references latest state

### BUG-003: Missing Capacity Validation Before Payment

**Files:**
- `src/components/features/checkout/CheckoutForm.tsx`
- `src/app/[locale]/(public)/experiences/[slug]/checkout/page.tsx`

**Problem:**
Capacity only checked at form submission, not before user fills form.

**Fix Required:**
1. Add capacity check on checkout page mount
2. If capacity insufficient, show error and disable form
3. Add real-time capacity display on checkout summary
4. Block submit button if guests > remaining capacity

### BUG-013: No Availability Recheck on Checkout Load

**File:** `src/app/[locale]/(public)/experiences/[slug]/checkout/page.tsx`

**Problem:**
User can sit on checkout page while spots get booked by others.

**Fix Required:**
1. Add `useEffect` to validate availability on mount
2. Show loading state during validation
3. If no longer available, redirect to booking page with message
4. Consider adding periodic recheck (every 60s) for long sessions

### BUG-023: Stale Closure in BookingWidget

**File:** `src/components/features/booking/BookingWidget.tsx`

**Problem:**
```typescript
const [guests, setGuests] = useQueryStates({
  guests: parseAsInteger.withDefault(experience.minCapacity),
});
// Default doesn't update if experience changes
```

**Fix Required:**
1. Add effect to reset guests when experience.id changes
2. Use `useCallback` with proper dependencies
3. Ensure guest count resets to `minCapacity` on experience change

### BUG-003b: Continue Button Not Disabled on Booking Page

**File:** `src/components/features/booking/BookingWidget.tsx:42`

**Problem:**
The `isValid` check does NOT validate against `remainingCapacity`, only `maxCapacity`:

```typescript
// CURRENT (broken) - Line 42
const isValid = date && time && guests >= experience.minCapacity && guests <= experience.maxCapacity;

// This allows navigation to checkout even when guests > remainingCapacity!
```

**Scenario:**
1. Experience has `maxCapacity: 10`
2. User selects date/time with only 3 spots remaining
3. User can still select 8 guests (within maxCapacity but exceeds remaining)
4. Button stays enabled, user goes to checkout
5. Only THEN they see the error (bad UX!)

**Fix Required:**
Update the `isValid` check to include `remainingCapacity`:

```typescript
// FIXED
const isValid = date && time &&
  guests >= experience.minCapacity &&
  guests <= experience.maxCapacity &&
  (remainingCapacity === null || guests <= remainingCapacity);
```

**UX Enhancement:**
Show message when capacity is exceeded:
```tsx
{remainingCapacity !== null && guests > remainingCapacity && (
  <Alert variant="warning">
    {t('booking.capacityExceeded', { remaining: remainingCapacity })}
  </Alert>
)}
```

### BUG-029: Booking Confirmation Email Not Sending

**Files:**
- `src/app/api/webhooks/stripe/checkout/route.ts` (lines 169-194)
- `src/server/services/email.service.ts`
- `.env` (RESEND_API_KEY)

**How Emails Should Work:**
Emails are sent via Stripe webhook (`checkout.session.completed`), NOT at booking creation:

1. User completes Stripe checkout
2. Stripe sends webhook to `/api/webhooks/stripe/checkout`
3. Handler updates booking to `CONFIRMED` and sends emails

**Potential Causes:**

1. **Resend API Key not configured:**
```typescript
// email.service.ts:33-39
if (!resend) {
  console.log('[Email] Resend not configured, skipping email');
  return true;  // Silent success - looks like it worked!
}
```

2. **Stripe webhook not registered:**
- Webhook URL not configured in Stripe Dashboard
- Webhook secret mismatch
- Local development without Stripe CLI forwarding

3. **Silent failures:**
```typescript
// route.ts:191-194
catch (error) {
  console.error('Failed to send confirmation email:', error);
  // Error swallowed - booking still confirmed but no email
}
```

**Fix Required:**
1. Verify `RESEND_API_KEY` is set in environment
2. Verify Stripe webhook is configured for `checkout.session.completed`
3. Add error alerting (not just logging) for email failures
4. Consider fallback: send email from checkout action if webhook fails

**Debugging Steps:**
```bash
# Check if Resend is configured
echo $RESEND_API_KEY

# For local dev, forward Stripe webhooks
stripe listen --forward-to localhost:3000/api/webhooks/stripe/checkout

# Check logs for email sending
grep -r "Resend not configured" .next/server/
```
