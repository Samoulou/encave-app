# Story 10.1: Experiences Page Performance Optimization

## Status

Done

## Story

**As a** visitor browsing experiences,
**I want** the /experiences page to load in under 500ms,
**so that** I have a fast, responsive browsing experience.

## Issues Addressed

| Issue ID | Severity | Description |
|----------|----------|-------------|
| PERF-010 | P1 | /experiences page loads in 1.8s (target: <500ms) |
| PERF-011 | P1 | Missing composite index on Experience (status, wineryId) |
| PERF-012 | P1 | Expensive `availabilitySlots.some.isActive` subquery on every request |
| PERF-013 | P2 | Cache keys too granular - poor hit rate |
| PERF-014 | P2 | `getExperienceCommunes` queries winery table inefficiently |

## Acceptance Criteria

### AC1: Database Index Optimization (P1 - PERF-011)
1. Add composite index `@@index([status, wineryId])` on Experience
2. Add index on AvailabilitySlot for `(experienceId, isActive)` if missing
3. Run migration successfully on production
4. Query execution time reduced by 50%+

### AC2: Denormalize hasActiveSlots (P1 - PERF-012)
1. Add `hasActiveSlots Boolean @default(false)` field to Experience model
2. Create migration to populate existing data
3. Update AvailabilitySlot create/update/delete to sync `hasActiveSlots`
4. Update `searchExperiences` to use `hasActiveSlots: true` instead of subquery
5. No functional regression - same results returned

### AC3: Cache Key Optimization (P2 - PERF-013)
1. Normalize cache keys (sort params, remove undefined)
2. Reduce cache key cardinality for common queries
3. Increase cache revalidation time for communes (static data)
4. Cache hit rate improved (measurable in logs)

### AC4: Communes Query Optimization (P2 - PERF-014)
1. Query Experience table directly instead of Winery
2. Use `hasActiveSlots` field for filtering
3. Reduce query complexity and execution time

### AC5: Performance Verification (P1)
1. /experiences page loads in <500ms (cold cache)
2. /experiences page loads in <200ms (warm cache)
3. All existing tests pass
4. No functional regression

### Current Query Performance Issue

```typescript
// BEFORE: Expensive nested subquery (1.8s)
where: {
  status: ExperienceStatus.PUBLISHED,
  winery: { status: 'VERIFIED' },
  availabilitySlots: { some: { isActive: true } }, // <- JOIN + subquery
}

// AFTER: Simple indexed field lookup (<500ms)
where: {
  status: ExperienceStatus.PUBLISHED,
  winery: { status: 'VERIFIED' },
  hasActiveSlots: true, // <- Direct field, indexed
}
```

### Sync Helper Implementation

```typescript
// src/server/actions/availability.ts
async function syncExperienceHasActiveSlots(experienceId: string) {
  const hasActive = await db.availabilitySlot.count({
    where: { experienceId, isActive: true }
  }) > 0;

  await db.experience.update({
    where: { id: experienceId },
    data: { hasActiveSlots: hasActive }
  });
}
```

### Cache Key Normalization

```typescript
function normalizeSearchParams(params: ExperienceSearchParams): string {
  const normalized = Object.entries(params)
    .filter(([_, v]) => v !== undefined && v !== null && v !== '')
    .sort(([a], [b]) => a.localeCompare(b))
    .reduce((acc, [k, v]) => ({ ...acc, [k]: v }), {});
  return JSON.stringify(normalized);
}
```

### Data Migration Script

```sql
-- Populate hasActiveSlots for existing experiences
UPDATE experiences e
SET has_active_slots = EXISTS (
  SELECT 1 FROM availability_slots a
  WHERE a.experience_id = e.id AND a.is_active = true
);
```
