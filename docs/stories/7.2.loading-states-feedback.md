# Story 7.2: Loading States & Visual Feedback

## Status

Done

## Agent Model Used

Claude Opus 4.5 (claude-opus-4-5-20251101)

## Story

**As a** user navigating the application,
**I want** immediate visual feedback when I click on links or buttons,
**so that** I know my action was registered and can wait confidently for the result.

## Problem Statement

Currently, when users interact with navigation elements (header links, login button, etc.), there is no visual feedback indicating that the click was registered or that a page transition is in progress. This creates uncertainty and may lead to:
- Multiple clicks on the same element
- Perception of application slowness or bugs
- User frustration and abandonment

## Bugs Addressed

| Bug ID | Severity | Description |
|--------|----------|-------------|
| BUG-034 | P2 | No visual feedback on navigation clicks (header links) |
| BUG-035 | P2 | No loading state on login/connection page buttons |
| BUG-036 | P2 | Missing skeleton loaders during data fetching |

## Acceptance Criteria

### AC1: Navigation Progress Bar
1. When navigating between routes, a burgundy progress bar appears at the top of the viewport
2. Progress bar is 3px tall with a subtle glow effect
3. Bar progresses smoothly from 0% to 100% during navigation
4. Bar fades out gracefully when navigation completes

### AC2: Button Loading States
1. Login/Sign-in buttons show a spinner when clicked
2. Buttons are disabled during loading to prevent double-clicks
3. Button text changes to indicate action in progress (e.g., "Connexion...")
4. Button width remains stable during loading state

### AC3: Skeleton Loaders
1. Experience listing page shows skeleton cards while loading
2. Domain listing page shows skeleton cards while loading
3. Dashboard shows skeleton layout while loading
4. Skeletons match the shape and size of actual content

### AC4: Accessibility
1. Loading states are announced to screen readers (aria-busy, aria-live)
2. Animations respect `prefers-reduced-motion`
3. Loading indicators have sufficient color contrast (WCAG 2.1 AA)

## Dev Notes

### Key Implementation: providers.tsx

```tsx
'use client';

import { AppProgressBar as ProgressBar } from 'next-nprogress-bar';

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <>
      {children}
      <ProgressBar
        height="3px"
        color="#cc2d55"
        options={{
          showSpinner: false,
          easing: 'ease',
          speed: 300,
          minimum: 0.08,
          trickle: true,
          trickleSpeed: 200,
        }}
        shallowRouting
      />
    </>
  );
}
```

### Key Implementation: globals.css

```css
/* NProgress Customization */
#nprogress {
  pointer-events: none;
}

#nprogress .bar {
  background: linear-gradient(90deg, #cc2d55 0%, #ab2046 50%, #cc2d55 100%);
  position: fixed;
  z-index: 9999;
  top: 0;
  left: 0;
  width: 100%;
  height: 3px;
  box-shadow: 0 0 8px rgba(204, 45, 85, 0.5);
}

#nprogress .peg {
  display: block;
  position: absolute;
  right: 0;
  width: 100px;
  height: 100%;
  box-shadow: 0 0 10px #cc2d55, 0 0 5px #cc2d55;
  opacity: 1;
  transform: rotate(3deg) translate(0px, -4px);
}

@media (prefers-reduced-motion: reduce) {
  #nprogress .bar {
    transition: none;
  }
  #nprogress .peg {
    display: none;
  }
}
```

### Key Implementation: Skeleton Component

```tsx
// src/components/ui/skeleton.tsx
import { cn } from '@/lib/utils';

export function Skeleton({
  className,
  ...props
}: React.HTMLAttributes<HTMLDivElement>) {
  return (
    <div
      className={cn('animate-pulse rounded-md bg-stone-200', className)}
      aria-hidden="true"
      {...props}
    />
  );
}
```
