# Story 12.2: Authentication & Login Flow Improvements

## Status

Ready for Review

## Story

**As a** user logging into the application,
**I want** to see relevant imagery and be redirected to the appropriate dashboard after login,
**so that** I have a cohesive Valais wine experience and can immediately access my relevant features.

## Problem Statement

User feedback identified 2 issues with the login experience:

1. **Wrong Imagery**: Login page photo is not from Valais - breaks regional branding
2. **No Smart Redirect**: After login, users are not redirected to their role-specific dashboard (client vs winemaker)

## Acceptance Criteria

### AC1: Valais-Themed Login Image
1. Login page displays an authentic Valais wine region image
2. Image showcases vineyards, mountains, or wine culture of the region
3. Image is properly licensed for commercial use
4. Image optimized for web (WebP, lazy loading)
5. Alt text describes the image for accessibility

### AC2: Smart Post-Login Redirect
1. After successful login, user is redirected based on their role:
   - **Winemaker/Encaveur**: Redirect to `/dashboard/bookings`
   - **Visitor/Client**: Redirect to `/dashboard` or previous page (returnUrl)
   - **Admin**: Redirect to `/admin`
2. If `returnUrl` query param exists, redirect there instead (for protected page access)
3. Redirect uses locale-prefixed URL
4. Loading state shown during redirect

### AC3: Session Persistence
1. Session persists across page refreshes
2. "Remember me" functionality works if implemented
3. Session timeout handled gracefully

## Technical Details

### Current Login Flow (Investigation)

```
1. User visits /login
2. Enters credentials
3. Auth provider validates
4. ??? (current redirect behavior unclear)
```

### Proposed Login Flow

```
1. User visits /login (with optional ?returnUrl=)
2. Enters credentials
3. Auth provider validates
4. Fetch user role from session/database
5. Redirect based on:
   - returnUrl param (if present and valid)
   - User role (winemaker → /dashboard/bookings, visitor → /dashboard)
```

### Security: Open Redirect Prevention

```typescript
// Validate returnUrl before redirect
const isValidReturnUrl = (url: string): boolean => {
  try {
    const parsed = new URL(url, window.location.origin);
    // Only allow same-origin redirects
    return parsed.origin === window.location.origin;
  } catch {
    return false;
  }
};
```

### Role Detection

```typescript
// Example role detection in auth callback
const userRole = session?.user?.role;

switch (userRole) {
  case 'WINEMAKER':
    return redirect(`/${locale}/dashboard/bookings`);
  case 'ADMIN':
    return redirect(`/${locale}/admin`);
  default:
    return redirect(`/${locale}/dashboard`);
}
```
