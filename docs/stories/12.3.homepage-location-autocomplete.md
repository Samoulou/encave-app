# Story 12.3: Homepage Location Autocomplete with Proximity Search

## Status

Draft

## Story

**As a** visitor on the homepage,
**I want** to search by typing a location (city, village, or commune) with autocomplete suggestions,
**So that** I can quickly find wine experiences near that specific location, ordered by proximity.

## Problem Statement

Current homepage search only supports keyword text search. Users looking for experiences in a specific location (e.g., "Uvrier") must:
1. Navigate to /experiences page
2. Find and use the commune dropdown filter
3. Hope the location is listed

This friction reduces discoverability. Competitors like ruedesvignerons.com offer intuitive location autocomplete that guides users to relevant experiences immediately.

2. User selects "Uvrier" → navigates to `/experiences?location=uvrier&lat=46.24&lng=7.42`
3. Results page shows: First experiences IN Uvrier, then nearby experiences sorted by distance

   - With location: `/experiences?location={slug}&lat={lat}&lng={lng}`

### AC4: Proximity-Based Search Results

1. Extend `/experiences` page to accept `location`, `lat`, `lng` query params
2. When location params present:
   - First: Show experiences WHERE winery is in exact location (village/commune match)
   - Then: Show experiences within 10km, sorted by distance (nearest first)
   - Then: Show experiences within 25km, sorted by distance
   - Finally: Show remaining experiences with distance indicator
3. Distance calculation using Haversine formula
4. Display distance badge on each ExperienceCard (e.g., "~5 km")
5. Results header: "Expériences près de {location}" instead of generic title
6. If no experiences in exact location, show helpful message: "Aucune expérience à {location}, mais découvrez ces caves à proximité"

### AC5: Geolocation Enhancement (Optional/Future)

1. "Use my location" button in search (requires user permission)
2. If granted, pre-sort autocomplete suggestions by distance from user
3. Search results also sorted by distance from user's actual location
4. Graceful fallback if geolocation denied/unavailable

## Technical Implementation Notes

### Distance Calculation (Haversine)

```typescript
function calculateDistance(
  lat1: number, lng1: number,
  lat2: number, lng2: number
): number {
  const R = 6371; // Earth radius in km
  const dLat = (lat2 - lat1) * Math.PI / 180;
  const dLng = (lng2 - lng1) * Math.PI / 180;
  const a = Math.sin(dLat/2) * Math.sin(dLat/2) +
            Math.cos(lat1 * Math.PI / 180) * Math.cos(lat2 * Math.PI / 180) *
            Math.sin(dLng/2) * Math.sin(dLng/2);
  const c = 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1-a));
  return R * c;
}
```

### Database Query Strategy

Option A: Calculate in JS (simpler, fine for <100 wineries)
```typescript
const sorted = experiences
  .map(exp => ({ ...exp, distance: calculateDistance(...) }))
  .sort((a, b) => a.distance - b.distance);
```

Option B: PostGIS extension (better for scale)
```sql
SELECT *,
  ST_Distance(
    ST_MakePoint(longitude, latitude)::geography,
    ST_MakePoint($lng, $lat)::geography
  ) / 1000 as distance_km
FROM wineries
ORDER BY distance_km;
```

**Recommendation:** Start with Option A, migrate to PostGIS if performance degrades.
